منبع: نمونه خروجی مستند اندپوینت «اطلاعات همه نمادها» در مستندات عمومی سورس‌آرنا. ستون «تأیید» یعنی کلید در مستندات عمومی دیده شد؛ «تأییدنشده» یعنی نام کلید حدس است و باید با پاسخ زنده بررسی شود (وظیفه D-03).

| فیلد استاندارد | کلید منبع | تأیید |
| --- | --- | --- |
| ins_code | instance_code | ✓ |
| symbol | name | ✓ |
| price_last (آخرین) | close_price | ✓ (در نمونه مستند، تغییر ۵٪ برای آخرین در برابر ۰.۳۹٪ برای پایانی) |
| price_close (پایانی) | final_price | ✓ |
| price_first، price_max، price_min | first_price، highest_price، lowest_price | ✓ |
| trade_count، volume، value | trade_number، trade_volume، trade_value | ✓ |
| ind_buy_vol، inst_buy_vol، ind_sell_vol، inst_sell_vol | real_buy_volume، co_buy_volume، real_sell_volume، co_sell_volume | ✓ |
| ind_buy_count | real_buy_count | ✓ |
| ind_sell_count | real_sell_count | ✗ تأییدنشده — **لازم برای پول داغ فروش** |

| price_yesterday | yesterday_price | ✗ تأییدنشده |

# BrsApi (آداپتور `internal/source/brsapi.go`، وظیفه D-03)

منبع: پاسخ زنده اندپوینت «همه نمادها» (۱۴۰۵/۰۷/۰۳، بازار بسته؛ داده روز معاملاتی ۱۴۰۵/۰۷/۰۱ یعنی ۲۰۲۶-۰۹-۲۳) و نمونه عمومی فروشنده. آزمون قرارداد: `internal/source/testdata/brsapi_allsymbols_type{1,4}.json` (۲۰ ردیف واقعی، بدون کلید).

- **درخواست:** `GET https://api.brsapi.ir/Tsetmc/AllSymbols.php?type=1&key=…` (`type=1`: سهام، حق تقدم و صندوق‌ها، ۱۶۰۸ ردیف؛ `type=4`: اوراق، ۵۹۷ ردیف با همان کلیدها). کلید فقط از `BRSAPI_KEY` خوانده می‌شود و چون در query است، هر خطا با `redact()` پاک می‌شود (شکل خام و URL-encoded). سرآیند `User-Agent` مرورگر فرستاده می‌شود (دیوار آتش فروشنده).
- **خطا:** پاسخ غیر ۲۰۰ یک شیء JSON است: `successful:false` و `status` و `message_error` و `account` (نوع پلن، مصرف امروز و سقف آن، مصرف ۵ دقیقه و سقف آن، `request_block`). آداپتور این‌ها را بدون کلید گزارش می‌کند.

| فیلد استاندارد | کلید BrsApi | یادداشت |
| --- | --- | --- |
| ins_code | `id` | کد داخلی TSETMC. در پاسخ زنده **عدد** JSON است تا 7.2e16 (بزرگ‌تر از دقت float64؛ خواندن با `UseNumber`). در نمونه عمومی بیشتر ردیف‌ها **رشته** هستند؛ هر دو پذیرفته می‌شود. کلید پایدار است و `l18` فقط برای نمایش است. |
| symbol | `l18` | در این پاسخ یکتاست. `l30` نام کامل است و نگاشت نمی‌شود. |
| price_last، price_close، price_first، price_yesterday، price_min، price_max | `pl`، `pc`، `pf`، `py`، `pmin`، `pmax` | قیمت ≤ ۱ ریال **جانشین** است و ناموجود ثبت می‌شود (پایین را ببینید). |
| price_limit_min، price_limit_max (فیلد جدید) | `tmin`، `tmax` | دامنه مجاز. مقدار ≤ ۱ یعنی «بدون دامنه» و ناموجود ثبت می‌شود (`FPriceLimits`). |
| trade_count، volume، value | `tno`، `tvol`، `tval` | |
| ind/inst buy/sell vol | `Buy_I_Volume`، `Buy_N_Volume`، `Sell_I_Volume`، `Sell_N_Volume` | در همه ۱۶۰۸ ردیف: حقیقی + حقوقی = حجم کل، برای هر دو سمت. |
| ind/inst buy/sell count | `Buy_CountI`، `Buy_CountN`، `Sell_CountI`، `Sell_CountN` | ✓ هر چهار فیلد (این همان فیلدهایی است که در سورس‌آرنا تأیید نشده بود) |
| book (۵ سطح) | `zd1..5`/`qd1..5`/`pd1..5` (خرید: تعداد، حجم، قیمت)، `zo`/`qo`/`po` (فروش) | صفر یعنی سفارشی در آن سطح نیست (مقدار واقعی). نبودن هر یک از ۳۰ کلید یعنی `book` ناموجود. |
| source_time | — | **زمان snapshot وجود ندارد.** `time` فقط ساعت آخرین رخداد نماد است، بدون تاریخ (۰۶:۱۰ برای نماد بدون معامله، که احتمالاً بازنشانی روزانه فروشنده است؛ ۱۲:۳۰ برای سهام؛ ۱۷:۵۹ برای طلا). پس `source_time` برابر زمان دریافت است و `source_time_estimated=true`. `ltd`، `ltt` و `m` در این پاسخ **نیستند**. |

**قالب داده:** عددها عدد JSON هستند (نه رشته). رقم فارسی در فیلدهای عددی نیست (در کدال هست). اعشار فقط در `plp`، `pcp` و `pe` است. `eps` و `pe` برای صندوق‌ها و اوراق `null` است.

نمادهای IRTK نقره‌ای که «نقره» در نامشان نیست (مثل نقرابی، نقران، سیلوا، پلاتا) باید دستی بازبینی شوند. **هشدار تقویم:** آخرین رخداد صندوق‌های درآمد ثابت و اوراق تا ۱۷:۳۰ است، ولی تقویم جلسه درآمد ثابت را ۰۸:۳۰ تا ۱۵:۰۰ فرض کرده (تأییدنشده). همچنین طلا تا ۱۸:۴۶ دیده شد. این دو با اطلاعیه رسمی تطبیق داده شوند.

بنا بر صفحه‌های فروشنده، پلن حرفه‌ای ۱۰۰۰ تا ۴۰۰۰ درخواست در ۵ دقیقه دارد (در پنل تأیید شود). اجتماع جلسه‌ها ۹ ساعت و ۳۵ دقیقه است. با پلن رایگان کمترین فاصله برای `type=1` حدود ۳۴۹ ثانیه است و برای «فقط جلسه سهام» (۳ ساعت و ۴۵ دقیقه) حدود ۱۳۷ ثانیه. فاصله ۵ ثانیه‌ای حدود ۶۹۰۰ درخواست در روز می‌خواهد. collector با `SOURCE=brsapi` پیش از شروع بودجه را می‌سنجد و اگر `POLL_INTERVAL` بیش از `BRSAPI_DAILY_LIMIT` یا `BRSAPI_5MIN_LIMIT` باشد **شروع نمی‌شود**، و کمترین فاصله مجاز را اعلام می‌کند. آداپتور هم سقف روزانه را در خود نگه می‌دارد (`ErrBudget`: بیش از سقف، درخواستی فرستاده نمی‌شود). بالا بردن این دو مقدار فقط پس از ارتقای پلن و تصمیم مالک مجاز است.
