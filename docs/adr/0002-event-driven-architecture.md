# ADR-0002: معماری رویدادمحور و انتخاب فناوری هسته

- وضعیت: پذیرفته‌شده
- تاریخ: ۱ مهر ۱۴۰۵

## تصمیم
- سرویس‌های مسیر داغ (collector، engine، gateway) به **Go**: هم‌روندی ساده، باینری مستقل، مصرف حافظه کم.
- گذرگاه: **NATS JetStream** (ساده‌تر از Kafka برای این مقیاس؛ نگهداری پیام و بازپخش).
- ذخیره سری زمانی: **ClickHouse**؛ کاربران و تنظیمات: **PostgreSQL**؛ وضعیت لحظه‌ای: **Redis**.
- تحویل به مرورگر: **Centrifugo** (وب‌سوکت با بازیابی پیام پس از قطع اتصال).
- تحلیل، بک‌تست و مدل‌ها: **Python** (Polars، DuckDB، LightGBM) — فاز ۲.

## پیامدها
- موتور محاسبه تابع خالص روی (snapshot قبلی، snapshot فعلی) است؛ بازپخش یک روز ضبط‌شده دقیقاً همان خروجی را می‌دهد.
- موتور ایمن برای هم‌روندی نیست؛ مقیاس‌پذیری با تقسیم نمادها بین نمونه‌ها بر اساس `ins_code`.
